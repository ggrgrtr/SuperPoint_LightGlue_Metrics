Программа проверяет падение метрик `LightGlue` при изменении размерности дескриптора `Superpoint` и при уменьшении размера параметра дескриптора

Для работы использовал датасет `HPaches`, в котором имеются последовательности изображений с изменением освещения и смещением камеры. 1 изображение - опорное, остальные 5 - для мэтча ключевых точек. В каждой последовательности присуотствует 5 текстовых файлов с гомографиями `3x3`, которые математически показывают преоразование опорного изображение в другие.
Чтобы не менять входные слои `LightGlue`, я использовал `PCA` для изменения размерности дескриптора и псевдо квантование.
Оба метода имитируют потерю информации для дескриптора, при этом не меняя его свойства, чтобы обученный мэтчер `LightGlue` мог его принять.

Программа работает в основной функции `run(config)` с декоратором `@torch.no_grad()`, чтобы не вычислялись градиенты при обратном проходе слоев и веса моделей не изменялись.

Вся работа у меня происходит на `cpu`, но если использовать например гугл колаб, можно изменить на куда:0. В функциях при приобразовании в `numpy` везде используется отдельный переход только на `cpu`. Проблем не возникнет.
Создаются объекты `Superpoint` и `LightGlue` в режиме чтения.

Программа проходит по папкам, создает объекты пары `HPatchesPair` вида опорное изображение + второе изображение + гомография. Добавляет их в список из объектов
Часть пар используется для настройки `PCA` через мат. преобразование `SVD`. `PCA` анализирует взаимосвязь параметров дескприпторов всех ключевых точек, суммарно переданных изображений. Это предстаетавляется в виде массива `numpy` `[пары x 1024 точки, 256 параметров]`. Находится средний дескриптор, вычетается из массива, далее `SVD` возвращает сортированные по изменчивости направления каждого параметра в дескрипторе и сохраняет первые `k` компонент в `self.components_` объекта `PCA(k)` из кортежа `k=(128, 64, 32)`. Они будут использоваться преобразования дескриптора с потерей информации. `PCA` нужен, чтобы при сжатии размерности дескриптора сохранить самые ценные связи параметров

Список пар для оценки метрик исключает пары, использованные в настройке `PCA`.

Далее создается словарь `variants` с типами преобразований (в том числе `None`) и их порогами.
Создается словарь stats с названиями преобразований, типами метрик и полученными значениями.

## 1 цикл
В цикле при проходе по парам изображений.
`Superpoint` находит ключевые точки и создает дескрипторы для 2х изображений.
Для этих дескрипторов проходимся по словарю `variants` и выпоняем преобразования по очереди в словаре. 
Псевдо квантование работает за счет потери информации как при сжатии параметра до конкретной битности, при этом сохраняя тип `float32`. Для дескриптора находится макс и мин значения, для диапазона которых находится шаг для каждой битности вида `2^k`. Параметры дескриптора округляются до ближайшего значения битности за счет вычета минимального значения и деления на шаг. Затем битность параметра возвращается при умножении на шаг и добавлении мин. значения. Но из-за округления, уникальных значений остается столько же, сколько бит было указано при квантовании. Остальные параметры повторяют значения уникальных. Так происходит потеря информации при сохранении битности. подходящей для `LightGlue`.

Далее мэтчер находит соответствия дескрипторов точек каждой пары по всем преобразованиям и без преобразования. 

Находим значения ошибок `MMA` и среднее востановление гомографий, в том числе и для сопоставленных точек, дескрипторы которых не изменялись. Это нужно, чтобы найти базовые значения метрик для `LightGlue`, с которыми потом будут сравниваться метрики сопоставлений преобразованных дескрипторов.
`MMA` находит расстояние между правильным положением совпавшей точки и предположительным. Передаем координаты __совпадений__, правильную гомографию и пороги ошибок. Каждая точка опорного изображения, которая по мэтчу `LightGlue` предположительно совпала с точкой второго изображения, по своему положению с помощью правильной гомографии преобразуется в предположительное положение второй точки. Затем это положение вычитается из положения второй действительной точки другого изображения. Для разности находится расстояние и получается ошибка. Затем она усредняется по всем ключевым точкам для порогов в (1, 3, 5, 10) пикселей и возвращается словарем в словарь `stats`

Функция corner_error проверяет восстанавливаемость геометрии 2го изображения по первому. 
`LightGlue` выдает пары дескприпторов совпавших ключевых точек. `cv2.RANSAC` по совпадениям создает гомографию, преобразующую координаты опорного изобажения во второе. В функции берутся 4 угла опорного изображения, по ним созданная и правильная гомографии находят положения углов для 2го изображения. Найденные матрицы положения сравниваются, мы вычисляем расстояние между разностью координат и усредняются по 4 расстояниям. Возвращается значение и передается в stats

Создаем список словарей для таблицы оценки метрик.
## 2 цикл
Проходим по списку variants, создаем новый словарь (строку) и записываем в нее тип преобразования, порог метрики, усредненное значение метрики по всем парам. Список угловых ошибок гомографии всех пар объединяется в одну метрику hAUC качества восстановления гомографии.
В функции error_auc угловые ошибки сортируются, для каждой величины определяется полнота, для каждого порога ошибки строится график, какая доля пар не переходит этот порог. Считается площадь под кривой от 0 до порога и делится на этот же порог. Получается нормализованное значение от 0 до 1

Выводим таблицу, насколько % каждая метрика отличается от мэтча непреобразованного входа. Разница метрик базового дескиптора и измененного, деленная на базовую метрику и умноженная на 100.




Данные выводятся в терминал. Значения метрик сохраняются в `ablation_results.csv`, таблица - в `a.txt`.
`PCA-128, PCA-64` почти не влияют на мэтчинг. `PCA 32` и псевдо квантование ухудшили точность востановления геометрии, вплоть до 4.9% для параметра 2 бит. `MMA` почти не изменилось нигде.
